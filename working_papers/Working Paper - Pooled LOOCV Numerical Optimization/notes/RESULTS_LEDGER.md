### What our logs actually preserve

1. **Explicit DGP equations and parameter grid:** documented mathematical trend recurrence, stochastic error laws, variance factors and noise correlation; source code is the executable specification.
2. **Randomness:** declared base seed, formula, per-scenario `seed` in per-method CSV, NumPy PCG-backed `default_rng`, deterministic R1/R3 pairing.
3. **Software and implementation:** Python, NumPy, SciPy versions, source commit SHA, fixed difference order and search bounds/scans in each run manifest.
4. **Experimental outputs:** per-method \(\widehat\lambda\), smoothness \(S\), observed LOOCV MSE, simulated latent reconstruction MSE when available, selected methods and failure diagnostics, aggregated JSON, small explanatory figures.
5. **Audit status:** reports distinguish **planned**, **CI smoke**, **executed/committed pilot**, **independent confirmatory**, and **mathematically certified**. None of the executed pilots establishes general superiority of a new optimization technique.

### Limits and safeguards

- Some runs store **generated outputs and exact regeneration settings** rather than full time-series arrays; to reproduce raw \(y,\tau\), use the original `git_sha` and explicit seeds. Re-running on a later changed branch should not be silently called a byte-for-byte reproduction.
- Hardware and exact CPU BLAS build are not fully specified for past runs; elapsed times are not portable comparisons. The stochastic Monte Carlo study is numerical, not a financial experiment.
- The nominal known-variance ratio is **not an oracle** for AR1 or heteroskedastic covariance regimes. Differenced Gaussian likelihood is an **extension**, *not an estimation technique claimed to have been introduced by Guerrero (2007)*.
- No extrapolation or future horizon enters this independent observed-series paper. Correlated errors may violate ordinary LOOCV's statistical interpretation.
- Store lightweight experiment results/notes in Git on branch `paper/pooled-loocv-numerical-optimization`. **Do not open PRs or merge**. Automatic CI may run only small validation smoke; full pilots, confirmatory campaigns, large figures, and document builds remain **manual-only**.

### G controlled change in DGP and evaluation precautions

- **New seed base 69000000**; `seed = base + N_index*10000 + sigma_eta_index*1000 + replicate`, so **mu levels share the identical simulated centered stochastic innovations and observation errors**, and R1 nests within R3. Never count mu-factor and R repetitions as independent Monte Carlo replicates. The **100 R3 method-comparison treatment pools share only 20 distinct simulated shock draws** (4 N×eta groups × five seeds), each deliberately reused at five mu levels. Statistical uncertainty must account for that shared-shock clustering.
- Unlike previous μ=0 pilots, **the true model's difference mean is `mu_factor * sigma_epsilon`**; when $mu\ne0$, imposing 0 changes the trend's expected polynomial degree.
- For the fitted Gaussian common GLS mean, a PRESS score that freezes full-data μ is marked **diagnostic/NOT honest CV**. The proposed joint pooled CV refits μ within each observation deletion using an exact PRESS identity, verified against explicit refit tests.
- Estimating μ **adds effective degrees of freedom** and changes its statistical interpretation; the previously used normalized S is retained as a nominal common λ coordinate, not true EDF of data-adaptive μ.
- The prior separate [Mean-Difference Forecasting paper](../../Working%20Paper%20-%20Trend%20Simulation%20and%20Mean-Difference%20Forecasting/README.md) deals with completed h-step *forecast* CV, NOT this retrospective observed-series LOOCV target.

### H operational and inferential safeguards

- **Code/pilot status:** fixed-d2 five-seed G pilot was executed; H's four-order 10k-per-stratum independent confirmation is **planned and implemented but not executed**. Do not confuse G's mean MSE values with large-H findings.
- H seed base **82100000**, formula `82100000 + d*1000000 + N_index*200000 + eta_index*100000 + replicate`, replicates 0–9999. This excludes G's earlier base 69000000 and tracks 160k distinct (d,N,eta,seed) draws, not 12.8M independent observations.
- Six shift-equivariant methods are computed once at μ=0 for each seed/R; only forced-zero μ Gaussian/LOOCV are recomputed at other μ values. Tests compare accelerated results to direct existing eight-method computation for d=1..4; this is CPU reuse, not more statistical evidence.
- Shards default to 100 independent base seeds, emit immutable `method_comparison.csv.gz`, `manifest.json`, `summary.json`. Compact aggregation verifies per-shard SHA256, disjoint seed intervals, one source commit, expected 10k reps **per** cell and matched paired-MSE summaries. Missing shards mark report incomplete.
- Very high-order (d=4,N=200) has extremely small positive penalty spectrum and huge quartic expected shift. Stable SVD of D and spectral caching were added, but numerical preflight and timing should be checked before launching full large runs. Fitted order is **fixed**, not selected using the known simulated latent truth.
- Non-Gaussian μ-shift scenarios (t, Gamma/skew, mixture, GARCH, Cauchy robust losses) form a **separate subsequent protocol** after H, not hidden additions to the Gaussian confirmatory family.

### Remaining decisions

**D has now been uploaded and audited.** In the 100 R=3 pools, Gaussian likelihood beat observed LOOCV on latent reconstruction MSE in 76/100 and by averaged MSE 0.542908 vs 0.620746, mostly driven by the AR1 error regime (20/20 paired wins, MSE 1.350641 vs 1.704392). Under iid Gaussian, mean 0.355507 vs 0.355433 essentially tied; R=1 Student-t innovations reverse the mean ordering. See [ROBUSTNESS_PILOT_AUDIT_2026-10-18.md](ROBUSTNESS_PILOT_AUDIT_2026-10-18.md). Before interpreting uncorrected LOOCV under AR1 as a predictive method, construct a separate covariance-aware or blocked-validation benchmark. New *independent* confirmatory seeds should only be run after this design and its inference are finalized.
